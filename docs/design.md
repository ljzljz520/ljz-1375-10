# 矿山工业遗产叙事站 —— 方案设计

> 目标：Web 端联动**矿井、轨道、工人社区**三类地点，后端保存**带时段的地点关系**、
> **口述许可**与**开放公告**；数据库在模型层就**区分历史空间与当前参观边界**；
> 井区合并、线路废弃、社区搬迁均以**事件**表达；今天的地图永远不覆盖历史照片定位。

---

## 0. 不可破坏的不变量（Invariants）

1. **历史与现实分轨**：历史几何/关系属于 `historical` 空间域，当前参观边界与可走路径属于
   `current` 空间域。任何查询、渲染、路径规划都不允许跨域把历史通道当当前路径。
2. **任何事实必须有来源、有许可、有有效区间**。无来源不入库；无许可不展示；
   照片撤权 / 受访者匿名后，读路径强制过滤。
3. **事件是唯一的变化表达方式**：井区合并、线路废弃、社区搬迁都生成 Event，
   并由事件产生/终结关系区间，不允许直接 UPDATE 抹掉旧状态。
4. **危险劳动与事故叙述的原证据不可被摘要替换**：逐字稿引用、卷宗原件引用与自动摘要分表存放，
   不确定标记（`certainty`、矛盾标记）在所有渠道（Web、打印、离线包）原样保留。
5. **参观功能只引用已批准区域**：路径规划在服务端用当前批准开放面做空间包含校验，
   历史轨道边只在 `historical` 图层展示，物理上不进入行人路由图。
6. **"时间未知"不等于"开放区间"**：`unknown` 哨兵与 `9999-12-31`（至今有效）严格区分；
   查询结果分"确定命中"与"可能命中"两层，不把猜测渲染成事实。
7. **渠道可能落后**：地图、逐字稿索引、图片说明各自带版本与同步状态；
   网页必须能向用户解释某渠道"尚未同步"，而不是悄悄展示旧数据当新数据。
8. **旧离线包必须可识别且可作废**：旧包返回（再次上线）时走版本协商与吊销列表，
   安全信息以服务端当前版本为准。

## 1. 核心方案选择：按时期生成空间视图 vs. 查询时解析有效区间

### 1.1 两方案对比

| 维度 | 方案 A：按时期预生成空间视图（快照） | 方案 B：查询时解析有效区间（双时态 + 事件溯源） |
|---|---|---|
| 模型核心 | 为每个时期切片预计算 place/relation/geometry 快照表 | 事实带 `[valid_from, valid_to)` 与记录时间区间，查询时做时态折叠 |
| 读性能 | 高（直接读快照） | 中（需要范围/约束索引、递归折叠） |
| 写入/改证 | 困难：一条来源修正要重算所有快照 | 容易：追加新断言，不删旧断言；自动可审计 |
| 矛盾来源 | 快照生成时被迫选一个版本 → 静默丢证 | 两个断言共存，标记 `conflict`，前端并列展示 |
| 时间未知 | 快照必须硬定一个切点，强迫猜测 | 可用 `unknown` 哨兵 + `possible` 层呈现 |
| 开放范围跨日 | 每个开放日一张快照，膨胀且易错 | 公告即带区间的事实，查询日做时间过滤即可 |
| 历史照片定位 | 历史快照与今日底图天然分离 | `realm` 分离 + 时态过滤，同样保证 |
| 可解释性 | 用户看到的是"某时期重建"，难展示分歧 | 可逐断言回溯来源、许可、记录时间 |
| 实现复杂度 | 快照生成/失效管线复杂 | 读模型复杂，但有成熟模式（bitemporal table） |
| 适合场景 | 只读、已定稿的展览时期 | 研究在持续、来源会修正、需合规审计的遗产叙事 |

### 1.2 决策：**B 为权威写入与事实层；A 仅作为派生只读缓存**

```
                ┌──────────────────────────────────────────┐
 写入（后台）──▶│ 事件 + 双时态断言（B，唯一权威，append）  │
                └───────────────┬──────────────────────────┘
                                │ 派生任务（版本化、可整体重建）
                 ┌──────────────┼───────────────────────────┐
                 ▼              ▼                            ▼
       AS-OF 时态查询 API  时期快照缓存(A, 只读)      搜索/逐字稿索引
```

理由：本场景来源会相互矛盾、时间常未知、授权会撤回、开放范围按日变更、
且事故叙述要求证据级审计——这些都是 A 作为权威模型会**静默丢信息**的地方。
A 的读性能优势通过"对已定稿展览时期生成版本化快照"保留，但：

- 快照表必须带 `snapshot_version`、`generated_at`、`as_of`，永不原地更新；
- 快照只是缓存，任何争议与撤回都能由 B 重建；
- 前端在快照与在线事实不一致时以在线 API 的版本号为准。

## 2. 时间语义（决定全系统行为）

### 2.1 区间

- 所有有效区间采用**半开** `[valid_from, valid_to)`。
- `valid_to = 9999-12-31` 表示**断言主张"至今仍有效"**（ongoing），不是未知。
- `valid_from = unknown` / `valid_to = unknown` 是独立哨兵，表示**不知道端点**；
  不得用 `9999`、`-infinity` 代替。
- 模糊时间（"1950 年代中期"、"大约 1958 年"）存两个字段：
  - `granularity`（year / decade / month …）
  - `fuzzy`（布尔）；展示为"约 1958 年""20 世纪 50 年代"，
    不允许在地图上伪装成精确切点。
- 每条事实同时携带**记录时间** `[recorded_from, recorded_to)`：
  来源迟到、修正、撤证都保留旧断言（审计需要），新断言用新的记录区间接管。

### 2.2 AS OF 查询与"确定 / 可能"两层结果

时间点 `t` 上判断区间 `[s,e)` 是否成立：

```text
def includes(s, e, t):
    # 确定命中：端点已知且 t ∈ [s,e)
    if known(s) and known(e): return s <= t < e
    # 起点未知：e 已知，t < e 只能判"可能"
    if unknown(s) and known(e): return None if t < e else False
    # 终点未知：s 已知，t >= s 只能判"可能"（不能断言它至今有效）
    if known(s) and unknown(e): return None if t >= s else False
    return None   # 两端都未知：永远"可能"，绝不"确定"
```

- `True` → 进入主图层与确定叙述；
- `None` → 进入"可能范围"图层（虚线/半透明）与"时间不确定"标注；
- `False` → 不出现。
- "至今仍开放"必须有明确近期来源支持 `9999`；仅因"没查到关闭记录"不得设 9999，
  应保持 `valid_to = unknown`（防止把"无知"当成"有效"）。

### 2.3 相互矛盾的来源

- 同一事实槽位（如某井某时期归属、某段轨道关闭年份）出现互斥断言时：
  **都保留**，各自挂 source、置信度、记录时间；该事实组置 `conflict`。
  - 禁止后台自动"选新/选权威"合并；冲突解决是一个**带操作人的显式事件**
    （`Event(type='assertion_resolution')`，记录取舍理由），被否定的断言仍可追溯。
  - API 返回 `assertions[]` 并列与一个可选 `resolved_choice`（无则为 null）。
  - 前端展示"资料存在分歧：来源甲称…，来源乙称…"，地图对冲突几何用并列描边/开关，
    不做平均化、不做融合。
- 来源可靠度用于排序与默认展示，**永不用于删除另一来源的证据**。

## 3. 数据模型概览（完整 DDL 见 `../db/schema.sql`）

### 3.1 空间域与地点

- `realm`：`historical`（历史空间）/ `current`（当前参观边界），全表级隔离。
- `place`：矿井、轨道线路、工人社区等**持续实体**（身份稳定，如"三号井""南干线""东山宿舍区"）。
  地点本身不直接存几何。
- `place_name_version`：地名随时段变化（合并、改名）。
- `place_geometry_version`：**几何也版本化、带区间、带来源与许可**。
  - 历史照片的点位落在其拍摄时期的几何版本上；
  - 历史几何可以是"复原图"（`geometric_quality = reconstructed`），渲染时必须标明。
- `historical_photo`：`shot_at_geom`（拍摄位置/被摄物位置）带
  `location_certainty`（precise / approximate / disputed / unknown），
  并强制 `realm='historical'` 语义——它只能在历史图层与时间轴联动中定位，
  绝不写入当前参观图层。今日底图上出现历史照片时必须挂"历史影像，位置为时期复原"角标。

### 3.2 带时段的地点关系

`place_relation`（每行一个带区间的断言）：

- `relation_type`：`merged_into`（井区合并）、`abandoned`（线路废弃为状态关系）、
  `relocated_to`（社区搬迁）、`connected_to`（轨道连接）、`served`（线路服务井区/社区）…
- `[valid_from, valid_to)` + unknown 哨兵 + `certainty` + `source_id[]`。
- 合并/废弃/搬迁的**业务事实**同时在 `event` 登记；关系区间由事件开闭。

### 3.3 事件（变化的唯一表达）

`event`：`merge` / `abandonment` / `relocation` / `opening_change` /
`consent_withdrawal` / `assertion_resolution` 等；

- 事件有发生时间（允许 unknown/fuzzy）、涉及地点、前后关系、依据来源、叙述。
- 写事件的事务内同步开闭对应 `place_relation` 区间（应用层编排，不做就地覆盖）。

### 3.4 开放公告与参观边界（current 域）

- `access_area`：当前**批准开放面**（Polygon），带审批来源、许可状态、
  `[valid_from, valid_to)`；`approval_status='approved'` 才可用。
- `opening_announcement`：开放公告（可按日/按时段），
  跨日变更 = 同一区域多条不重叠公告区间；`published_at` 未到的公告不生效。
- `walk_edge`：**当前行人可走图**（来自 current 域测绘，独立于历史轨道）。
  服务端在路径返回前做：边中点与缓冲区 `ST_Contains/ST_Within` 批准开放面的校验；
  不满足则拒绝并返回原因，不生成"绕行进入限制区"的路线。
- 历史轨道边另有 `historical_track_segment`，**没有任何外键或图计算连接到 walk_edge**，
  物理隔离，杜绝把废弃线路当步道。

### 3.5 叙述、事故与逐字稿

- `narrative`：叙事块（危险劳动、事故、日常），`severity` 不参与"弱化"逻辑；
  含 `uncertain_markers`（结构化不确定标记）与 `conflict_group_id`。
- `evidence_quote`：逐字稿/卷宗**原文引用**，带时间码或页码、source、许可。
  - 摘要在 `narrative.auto_summary`，且必须带 `summary_provenance`（模型/人工、生成时间）；
  - 展示时原文引用永远先于/并列于摘要，摘要不得单独呈现事故事实；
  - 视觉表现（地图动画、时间轴）不允许移除 `uncertain_markers`，
    不允许用淡化配色/折叠控件默认隐藏伤亡信息。
- `transcript_segment`：逐字稿分段，索引只索引"许可允许公开"的段。

### 3.6 口述许可、照片权利与撤回

- `consent`：口述许可（受访者、范围、地域、用途、`[valid_from,valid_to)`、状态）。
  - 匿名要求：`anonymization = full/pseudonym/none`；
    **在存储边界完成假名化**，真实身份与展示名分表（`interviewee_identity` 受限表），
    API 与索引只持有假名；full 匿名时连假名都不发布。
  - 许可收窄/撤回 → 追加 `consent_withdrawal` 事件 + 新许可区间；
    读路径以"当前生效许可"过滤叙述、逐字稿段、录音引用。
- `photo_right`：照片权利（授权范围、到期、撤回）。
  撤权（`revoked`）后：像素/缩略图从公开桶摘除、引用处替换为"资料已撤权"占位、
  **同步从地图、逐字稿索引、图片说明三个渠道删除/降级**（见第 4 节），
  且历史离线包通过吊销列表拦截。

### 3.7 来源与双时态列

每张事实表统一携带：

```text
source_id[]            -- 可多来源
certainty              -- definite / probable / disputed / unknown
recorded_from/recorded_to, recorded_by   -- 系统记录时间（修正/撤证审计）
```

## 4. 多渠道同步：地图、逐字稿索引、图片说明

### 4.1 版本化与同步状态

- 内容有单调递增 `content_version`；每个渠道维护 `channel_sync` 游标
  （地图切片、逐字稿索引、图片说明、离线包）。
- 每个渠道有独立状态：`synced / building / stale / failed / withdrawn`。
- 后台一次编辑在一个**内容版本**内提交；各渠道异步追赶，追平前：

```text
GET /status/channels →
  map:        {version: 412, state: "synced"}
  transcript: {version: 412, state: "building", note: "逐字稿索引重建中，约 10 分钟"}
  captions:   {version: 409, state: "stale",   note: "3 条图片说明尚未同步"}
```

- 前端顶栏/条目旁显示渠道状态徽标；未同步渠道的旧内容必须带
  "此渠道显示的是 v409，后台当前 v412" 的显式说明，**不允许假装一致**。
- 撤权/匿名收窄不走最终一致的"等待窗口"：先走**撤回快道**
  （向所有渠道写 tombstone、公开存储立即摘除），再补常规重建。

### 4.2 后台更新的编排（单内容版本）

```text
编辑提交（新事件/新许可/撤权）
   └─ 事务：写事实/事件/许可 → content_version+1
         ├─ 地图渠道：失效相关矢量切片 → 重建 → 更新游标
         ├─ 逐字稿索引：删除撤权段 → 增量索引 → 更新游标
         └─ 图片说明：重写受影响 caption/占位 → CDN 失效 → 更新游标
```

### 4.3 打印

- 打印安全信息（开放范围、禁入区、紧急联络、路径）**必须标注资料时间**：
  `安全信息截止 YYYY-MM-DD HH:mm（内容版本 n）`。
- 打印模板中历史轨道/历史通道用"历史图层"图示并注明"历史通道，非当前可走路径"，
  与当前路线在图例上彻底分离。
- 安全信息超过可配置时效（如 24h）时打印件出现醒目"请上网核对最新开放公告"提示。

## 5. 离线包与"旧包返回"

- 离线包带 `package_version`、打包时的 `content_version`、`expires_at`、清单哈希。
- App/网页再次上线时进行版本协商：上报本包版本，服务端返回
  `current / upgrade_required / revoked`。
- 服务端维护 `revoked_manifest`（因撤权、安全边界变化作废的包）。
  旧包在吊销列表内 → **安全相关图层与撤权素材拒绝展示**，强制升级；
  不在列表但已过期 → 可看历史叙事，但安全/开放信息页强制在线拉取，
  无网络则显示"当前开放状态未知，请勿据此进入"。
- 任何情况下离线历史几何都不会被路由模块使用（walk_edge 不打包进可路由结构，
  或打包时标注为纯展示）。

## 6. 关键 API（摘要）

| 方法/路径 | 作用 | 关键约束 |
|---|---|---|
| `GET /places/{id}?as_of=t&realm=...` | 地点时期视图（名称/几何/关系折叠） | unknown 端点返回 possible 层 |
| `GET /places/{id}/timeline` | 合并/废弃/搬迁事件时间轴 | 事件全部保留，含冲突标记 |
| `GET /map?as_of=t&realm=historical\|current` | 图层 | 历史照片只在 historical 出图 |
| `GET /access/open-areas?date=` | 某日批准开放范围 | 跨日公告做区间相交；未批准不返回 |
| `POST /route` | 当前参观路线 | 服务端开放面包含校验；越界拒绝 |
| `GET /narratives/{id}` | 事故/劳动叙述 | 原文引用+摘要+不确定标记同返 |
| `POST /admin/events` | 登记事件（合并/废弃/搬迁…） | 事务内开闭关系区间 |
| `POST /admin/consents` / `/withdrawals` | 许可与撤回 | 触发撤回快道 |
| `GET /status/channels` | 渠道同步状态 | 前端按此解释"尚未同步" |
| `POST /offline/handshake` | 旧包返回版本协商 | 吊销/过期/升级三态 |

## 7. 验收场景 → 机制对照

| 验收点 | 机制 |
|---|---|
| 轨道断裂 | `abandonment`/`track_break` 事件在断裂日终结旧边区间；历史图层显示断裂符号，current 步行图从不包含该边 |
| 开放范围跨日变更 | `opening_announcement` 多条区间按查询日相交；`GET /access/open-areas?date=` 逐日返回；切片带日期参数缓存 |
| 受访者匿名要求 | consent 追加匿名收窄 + withdrawal 事件；假名化在存储边界；索引/地图/说明三渠道 tombstone；旧离线包吊销 |
| 照片撤权 | photo_right=revoked；公开桶摘除；三渠道降级为"已撤权"占位；冲突/历史中不残留可定位像素 |
| 旧离线包返回 | handshake 版本协商 + `revoked_manifest` + expires_at；安全信息强制在线核对 |
| 不把历史通道当当前路径 | realm 隔离 + historical 边不入 walk_edge + 路由开放面校验 + 打印图例分离 |
| 时间未知 | unknown 哨兵、possible 图层、模糊时间文案，绝不写成精确点 |
| 来源矛盾 | 断言共存、conflict 标记、显式 resolution 事件、前端并列 |
| 事故叙述不被淡化 | 原证据分表、摘要必须附原文与标记、标记在各渠道不可移除 |

## 8. 为什么不选"纯时期视图"作为权威库（小结）

纯快照方案在**轨道断裂日期有争议**、**搬迁年份口述为"60 年代初"**、
**照片授权中途撤回**、**开放区域每天不同**这四类验收输入下，
要么在生成快照时被迫选择（丢证据），要么快照数量爆炸且无法审计撤回。
双时态事件模型把"事实、来源、许可、时间"四者独立保留，
时期视图降级为可随时重建的缓存，既满足展览性能，也满足证据与安全要求。
